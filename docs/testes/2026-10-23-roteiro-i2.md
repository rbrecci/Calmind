# Roteiro I2 em 23/10/2026: demonstração cruzada do RNF-61

Critério (etapa I2, seção 5 de [etapas-sprint2.md](../planejamento/etapas-sprint2.md)): o admin aprova um psicólogo no painel web e ele aparece no app, na mesma sessão.

**Resultado em uma frase:** a aprovação no painel web foi feita pela interface e comprovada com capturas; a aparição do psicólogo do lado do paciente foi comprovada pela API do catálogo (a mesma que o app consumiria), mas **o app não mostrou o psicólogo, porque ainda não tem tela de catálogo**. O critério não está fechado do jeito literal.

## Ambiente

- API Laravel em `http://localhost:8000` (`/admin/login` respondeu 200), banco `calmind` recém recriado com `migrate:fresh --seed`.
- Expo web em `http://localhost:8081`, com `EXPO_PUBLIC_USE_MOCK=false` no `app/.env` (ver [setup-frontend.md](../engenharia/setup-frontend.md)). A URL da API do app aponta para o IP da LAN, na porta 8000.
- Contas fictícias do seeder: ver `backend/database/seeders/UserSeeder.php` (admin, paciente Frodo Bolseiro, psicóloga pendente Jane Marple). Tokens abaixo estão mascarados.

## O que o roteiro mostra

1. Painel web e API leem o mesmo banco: a aprovação feita na interface Blade mudou o estado que a API do paciente devolve, sem reiniciar nada e na mesma sessão de teste.
2. Para um psicólogo aparecer no catálogo são três condições, não uma: cadastro aprovado pelo admin, documento enviado e perfil publicado pelo próprio psicólogo.

## Limites (o que não foi comprovado)

- **O app não exibiu o psicólogo aprovado.** O app abriu no navegador (Expo web) e autenticou contra a API real, mas não existe tela de catálogo. O lado "aparece no app" foi substituído pela chamada autenticada ao endpoint do catálogo, via `curl.exe`. Isso prova o dado compartilhado, não a tela. Para fechar a I2 literalmente falta a tela de catálogo no app (trabalho de código, fora do escopo desta execução).
- **A aprovação não foi feita sobre o estado puro do seed.** A Jane do seed não tem documento e o painel recusa aprovar. Foi preciso enviar o comprovante fictício e, depois, preencher e publicar o perfil, tudo pela API autenticada como a própria Jane. Mudanças de dados além da aprovação: um documento anexado, perfil preenchido e publicado. A bio gravada contém o erro de digitação "fficticio" (dado de demonstração, não corrigido).
- A confirmação manual anterior ao reset (relato do Saker no resumo de validação) não foi reaproveitada como prova.
- Não foi testado em celular físico nem em emulador, só no Expo web (comportamento de armazenamento do token difere na web, ver README do app).
- Não foi verificado se a Jane, depois de aprovada, aparece no painel de outros papéis; o escopo foi admin e paciente.
- Os tokens de login usados nos comandos não foram gravados neste arquivo.
